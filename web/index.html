          Crew

          The people you fly with. Star Citizen 4.9 and 4.10 log no party roster — there is no join event carrying a member list and no player id anywhere — so this is built from the only lines that name anyone: the toasts announcing that somebody in your party came online or dropped. Every number here is a floor, never a total. A friend who was already online when you grouped up and stayed until you logged off produces no toast at all, so an evening flown together can leave no trace. What these rows can be trusted to say is that these people were there — never that nobody else was.

          Item labels

          Star Citizen reads its English text from one file at startup, so replacing that file changes what the game calls things. It is text only — no binary, no memory, nothing the anti-cheat looks at — and it is the only thing this app writes outside its own folder. Restart the game for a change to take effect.

          StarStrings

          A community text mod by MrKraken that rewrites the game’s English text to read more usefully: contracts that award blueprints are tagged [BP], item names are shortened, contracts show the reputation they pay, and the mining guide is sorted by rarity. github.com/MrKraken/StarStrings — not written by, or affiliated with, this app.

          It works alongside the labels below. Both replace the same file, so whichever is installed second would otherwise remove the first. Install these in either order and the labels are rebuilt on top of StarStrings' text, so contract reputation tags and item labels are both there. Removing either one puts back exactly what it displaced.

          This writes into your game folder. It puts two files in your LIVE directory — Data\Localization\english\global.ini and USER.cfg — and nothing else; anything else in the download is refused. Whatever is already there is copied aside first, and Remove puts it back. A game patch may replace it, and then it simply is not installed any more.

          Label your items

          Writes what this app knows into the names themselves, in one bracket at the end: [S2B] is a size 2 grade B component, [H] is heavy armour, and * means nothing is known to sell it — so a thing worth carrying is obvious while you are standing over it. Four characters, because the median item name is already 21 and a third are over 24.

          It is a floor, not a rarity rating. Two things say an item is sold: your own receipts, which cannot be wrong because the game charged you, and UEX, which is broad but crowd-sourced — it misses 29 of the 106 items these logs prove were bought at a kiosk. Ship components and internals are left out: marking every name would mark most of them, and a mark on almost everything says nothing.

          Settings

          New versions

          Asks GitHub which release is newest and says so if it is ahead of this one. One request, carrying nothing but the request — no identifier, no version, no count of anything. When there is a newer one you are offered it, with its size, and nothing is fetched until you say so. The same check sits on the toolbar, under Settings.

          Last wipe

          A data wipe resets what your account holds, so logs from before one describe an account you no longer have — adding those sales to this account's income makes a wrong number, not a bigger one. Sessions before this date are kept and still parsed, they are simply not counted. Moving the date back brings every one of them straight back.

          Wipes come at different depths — some take aUEC and leave the hangar, some clear inventories and leave balances. Tick only what this one actually took; everything left unticked keeps its whole history.

          Community ship and trade reference

          Commodities, gear and prices no longer need this. All of it is read from your own install now, which is always the patch you are playing — and the install describes 26,028 items where this download describes 10,843. What it is still for: ship specifications, the ports a ship can fit, map positions, and a fuller table of what spawns where — the install covers 1,321 rows across 50 places against this download's 2,642 across 234. Ship cargo, speeds and shield totals are in your install too, but in files the game encrypts, so they cannot be read from there and this is the honest source for them. From StarCitizenWiki / scunpacked-data. Enabling downloads a set of public files (~110 MB, kept as a few MB) into local app data. Fetched only when you ask — nothing here goes out on a timer or at startup. A game patch adds ships the dump does not have yet, so this says which build it was made from and tells you when that is older than the patch your logs are on. Disabling deletes the local copy.

          UEX live prices

          Crowd-sourced market prices from uexcorp.space — a third party, separate from the community dataset. Enabling fetches the current price table and shows best sell prices on the Market page. On your click, unless you turn on the refresh below — the one thing here that may go out on its own.

          Extra feeds. Narrower tables that each serve one page — take only what you need. Every one is a separate download on your click, and can be dropped again without touching the rest.

          Report your prices back. Every logged kiosk sale carries an exact unit price at a known terminal — the numbers UEX datarunners type in by hand. With your own UEX application token and secret key (from your UEX account), you can contribute them. Keys are stored in local app data only; every report is a button you press, previewed first.

          Report a problem

          If a page is empty here and full for somebody else, this is what tells us why. It holds what the parser could not read — a count per unrecognised line and one example of each — with the counts behind each page, your game builds, and which optional data is turned on.

          Your logs stay here. The report is built from a list of things this app chose to include, not from a log with the private parts taken out, so there is nothing to miss: no handle, no character or account id, no folder names, no UEX keys. Nothing is sent anywhere — it saves a file you can read first and then attach to an issue.

          These are raw lines from your log, and they are the fastest way to fix a parser. Names and ids we recognise are replaced — but a line is only in here because the game changed its format, and a new format can write your name in a way nothing knows to look for yet. Read them before you send them.

          About

          The goal is a frictionless companion for Star Citizen — one that gathers the useful information the game already writes down, and hands it back to fellow players without asking anything of them.

          It exists because I went looking for it and it was not there. There are good Game.log tools, but none of them was a whole product built around an org and the things I wanted to keep track of — so I built the one I had been looking for, and it is free for the community to use, and meant to stay that way.

          No account, no configuration, no upload. It reads Game.log and the backups beside it, resolves the names from your own copy of the game, and shows you what is there. Nothing is written to the game directory, and the app connects to the internet only where you have said it may — the optional datasets from the Settings page, and, if you turn them on, the version check and the market-price refresh. Those last two are the only ones that go out without a click, and both are off until you say otherwise.

          There is a Discord for questions, bug reports and whatever the logs turn up next: discord.gg/AV3cDzRs39. It is the place to say a page looks wrong, which is worth more than it sounds: most of what this reads was found by somebody noticing a number that could not be right.

          Questions

          Why is my pledged ship, armour or gun missing?

          Nothing that arrives in your account is written to Game.log. A pledge, a pack, a rental or anything bought on the website is simply there the next time you look, and the game says nothing about it. It appears here the first time you actually use it — fly the ship, wear the armour, move the item — because that is the first moment there is a line to read.

          Why are my totals lower than I expected?

          Sessions from before the last wipe are kept but not counted, because a wipe ends one account and starts another. Settings → Last wipe says how many sessions that is, lets you move the date, and lets you say what the wipe actually took — some reset aUEC and leave your hangar alone. Nothing is deleted: move the date back and it all returns.

          Where did the kill counter go?

          Removed, because it could only ever read zero. Star Citizen 4.9 and 4.10 do not write kill or vehicle-destruction lines to Game.log at all — checked line by line across every backup on this machine: not one. A counter pinned at zero reads as a broken feature rather than a missing one, so the honest thing is to say so here instead of showing it.

          The parser for those events is written and tested against the old format, sitting dormant. If CIG starts logging them again the counter comes back with it.

          Why does the map not show where I am, exactly?

          No player position is logged. Location is inferred from discrete signals — inventory requests, quantum routes, spawns — so the map is a topology, not a radar, and every estimate carries a confidence rather than pretending to a precision it does not have.

          The overlay will not let me click the game.

          Press its 📌 pin button and clicks pass straight through. To get it back, right-click the tray icon and untick Pin overlay, or press Ctrl+Alt+O. It arrives unpinned, so it can be dragged where you want it first.

          Does it touch the game, or my account?

          No. It reads Game.log and the backups beside it, and nothing is written to the game directory, no memory is read and nothing is injected. It connects to the internet only where you have said it may, from the Settings page — and the two that can go out unattended, the version check and the market-price refresh, are both off until you turn them on.

          Does it phone home, or check for updates?

          It sends nothing about you, ever — no identifier, no usage, no statistics. It can look up whether a newer release exists, and only if you say yes: you are asked once, and Settings → New versions carries the switch and a Check now button. That look is one request to GitHub's public release feed, which carries nothing but the request. Nothing is downloaded or installed for you — you get a link to the release page.

          Something is wrong, or missing. Where do I say so?

          Please do. Message nekhron on Discord, or raise an issue at github.com/peans99/QuantumWake/issues. A log line that was parsed wrongly, with the line itself, is the most useful thing you can send.
